# The Application lifecycle ends at Submitted

Phase 0 exists to produce autonomous, individually tailored applications at volume, so a confirmed **Submitted** Application is the success event and the KPI. We dropped the outcome states from PRD §53/§54 (OUTCOME_PENDING, REJECTED, INTERVIEW, OFFER). The Candidate is never asked to track rejections or ghosting, and no hiring status is derived from outcomes. If an employer never responds, that is not an Outcome and never counts as a rejection. Post-submission tracking would have added a CRM-like workflow the Candidate has to feed, which cuts against "turn it on and walk away".

## Consequences

- **Outcome** stays in the language as an optional, later event on a Submitted Application (for example "Got an interview"), and email detection can add Outcomes in Phase 1.5. Neither is required in Phase 0.
- **Uncertain Submission** (the submit action may have gone through, but no confirmation was seen) is not Submitted and does not count as throughput. It is never retried automatically. The Candidate may confirm it either way, or leave it unresolved.
